# AI 对话内开发 12 步 checklist

> **定位**：§14 IRON_RULE 的**对话内轻量执行规范**。§14 定义了完整的 12 步骤状态机（flow_id + A轮/B轮 + 1000轮测试），那个是**正式开发活动**的强制执行版本。本文件是 AI 助手在**单次对话内的增量开发**必须执行的轻量 checklist，两者配合使用。

---

## 12 步轻量版（AI 对话内强制执行）

### ⛔ 铁律：前 7 步**不可跳过**

> **§14 MT_IR_D9**：检测到开发活动 → 必须先创建合法 flow_id。本 checklist 中的 STEP_1-PROPOSAL 对应对话内的"任务范围声明"，在 AI 工具链里等同创建轻量 flow_id（不写 DB，但必须在对话里明确落位）。

| # | 步骤 | AI 助手必须做什么 | 何时触发 |
|---|------|-------------------|----------|
| **1** | **范围声明** | 任务一句话总结 + 影响文件清单 + 前置依赖（如无明确依赖写 "无"） | **首次动手前必须先声明** |
| **2** | **Advisor 对齐** | 调 `AdvisorTool` 获取方向确认（有明确方案的小修除外） | 改代码前 |
| **3** | **代码定位** | `Glob`/`Grep`/`Read` 找到**准确**的修改位置（不允许"猜路径"） | 写代码前 |
| **4** | **实现** | `Edit`/`Write` 写代码 — 每处改动都要知道"改什么/为什么/改完会触发什么" | 修改中 |
| **5** | **py_compile** | 改完立刻 `python3 -m py_compile` 覆盖所有改动模块 | Edit/Write 结束后 |
| **6** | **冒烟测试** | 端到端跑一遍（单元 + 集成 + 降级分支），通过才能继续 | py_compile 通过后 |
| **7** | **diff 自检** | 读一遍改动后的完整方法/函数：有没有边界 case 没覆盖？有没有硬编码？有没有泄漏？ | 冒烟通过后 |

### ✅ 后 5 步（收尾时执行）

| # | 步骤 | 说明 |
|---|------|------|
| **8** | **前端/路由同步** | 如果改了 API，前端模板/路由是否需要同步改？改了 DB schema，ensure_schema 是否加了幂等 ALTER？ |
| **9** | **清理临时文件** | `/tmp/*.py` 冒烟脚本、调试输出文件 — 工作流结束前必须删 |
| **10** | **Todo 同步** | TodoWrite 把完成的任务标记 completed，加 summary 字段说明实际做了什么 |
| **11** | **交付总结** | 汇总改了哪些文件 / 加了什么能力 / 验证结果 / 遗留问题 |
| **12** | **下一步规划** | 下一轮最值得做的是什么？（没答案就停下来让用户决定） |

---

## 违反判定（哪些是"跳步"）

| 跳步类型 | 判定条件 | 后果 |
|----------|---------|------|
| **无范围声明直接写代码** | 没有先说明"改什么文件/做什么事" | ⛔ 必须停下来补 STEP_1 |
| **不调 Advisor** | 改方向/卡住/失败时不叫 Advisor | ⛔ 强制叫了再继续 |
| **猜路径** | 直接用硬编码路径 Edit，没先 Glob/Read 验证 | ⛔ 必须先定位 |
| **跳过 py_compile** | 改完多个文件直接进入冒烟 | ⛔ 先编译再冒烟 |
| **跳过冒烟** | 直接说"代码写完了" | ⛔ 必须至少单元验证 |
| **跳过清理** | 临时文件留在 `/tmp` 超过一天 | ⚠️ 下一轮开始前先清理 |

## 与 §14 IRON_RULE 的关系

```
本 checklist (AI 对话内)          §14 IRON_RULE (正式开发)
─────────────────────           ──────────────────────
STEP_1 范围声明          ←→     STEP_1_PROPOSAL (完整表单 + flow_id)
STEP_2 Advisor 对齐      ←→     STEP_2A_ROUND (4方讨论) + STEP_3_ZXF_DECISION
STEP_3-7 实现+验证       ←→     STEP_4 → STEP_9B (记录/对接/执行/验收/投喂)
STEP_8-12 收尾           ←→     STEP_10 (版本) → STEP_11 (Git) → STEP_12 (1000轮)
```

**适用场景**：
- ✅ AI 助手在对话内的增量开发（加函数/改路由/修 bug/优化）→ 用本 checklist
- ✅ 用户发起的**正式**开发活动（大功能/大重构）→ 两者都走：本 checklist 先快速收敛，然后按 §14 创建完整 flow_id 落库

**豁免**：
- 单文件 < 5 行的纯格式修改 → 可直接 Edit 后 py_compile
- 纯只读查询（Glob/Grep/Read/SearchCodebase）→ 不适用
- 用户明确说"跳过验证直接做" → **不可豁免**，必须至少 py_compile

## AI 助手自测清单（写完代码后默念一遍）

- [ ] 这次改的东西，用户能**直接感知**到吗？（API 调用得到新结果 / 新按钮 / 更准的输出）
- [ ] 有没有哪处异常没 try/except 包？
- [ ] 新增的表/列，ensure_schema 里加了幂等 ALTER 吗？
- [ ] 有没有硬编码路径/端口/URL？
- [ ] 降级分支测了吗？（Ollama 离线时、空输入时、DB 空表时）
- [ ] 有没有遗漏 TodoWrite summary？
- [ ] 临时文件删了吗？
